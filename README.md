# AgenticFeed 前端交互原型

基于现有 AgenticFeed 蓝紫品牌语言完成的纯前端 React 原型，覆盖信息 Feed、AgenticFeed Studio（创作者中心）与用户中心。所有数据与生成流程均为浏览器内模拟，不连接真实业务系统。

## 运行

```bash
npm install
npm run dev
```

开发服务默认监听 `0.0.0.0`。启动后，同一内网的同事可通过终端输出的 `Network` 地址访问，例如 `http://192.168.1.20:5173`；需确保系统防火墙允许对应端口。

生产构建检查：

```bash
npm run build
npm run preview
```

## 已实现的演示闭环

1. 在 Feed 中搜索、切换分类，并在“智能排序/最新消息”之间切换。
2. 进入独立的发布动态子页面，编辑正文与附件，选择信息来源、分类及组织可见范围。
3. 关注或取消关注信息来源，查看“同部门人在看”和推荐信息源。
4. 点击单条信息的 AI 图标，自动生成文章摘要，并围绕该信息继续追问讨论。
5. 转发内容，或选择具体 Studio 项目与文件夹保存为项目引用。
6. 在 Studio 新建不归属项目的独立对话，历史记录与项目树分开保存；项目内可管理资料与自定义子文件夹，并逐项勾选或全选对话来源。
7. 在 AI 对话框选择图像、PPT、视频、翻译、报告、图表等生成项并持续追问；生成物进入独立资产集合，不作为项目子文件夹。
8. 在右侧“项目资产”查看生成结果与任务历史，支持全选打包下载、预览/全屏、导入对话、分享至 Studio、单项下载、任务删除及栏位收起。
9. 在用户中心查看个人数据、项目与创作记录。
10. 在“偏好设置”中搜索、筛选、添加/移除约 10 个 Mock 海外 AI 信息源，也可录入自定义 RSS、官网或 API 地址，并配置主题、语言、推荐排序与通知简报。

## 需要配套建设的非前端功能

以下能力是本次改造真正上线所必需的服务端、算法、数据与运营能力。

### 1. 统一账号、组织与权限

- 对接企业 SSO/统一身份认证，维护集团—分公司—部门—员工组织树。
- 提供岗位、角色、数据范围与资源级权限校验，不能只依赖前端隐藏按钮。
- 为 Feed 内容、分享链接、Studio 会话、企业模板、生成产物和知识库条目建立统一授权模型。
- 支持离职、调岗、部门合并后的权限回收与数据归属迁移。

### 2. Feed 内容采集、发布与来源关系

- 海外 AI 资讯采集：接入 OpenAI、Anthropic、Google DeepMind、Meta AI、Microsoft 等官方 RSS/API/网页来源；处理时区、语言、正文抽取、去重、翻译、来源标记和失效检测。
- 来源账户体系：维护来源身份、认证状态、简介与关注关系，提供关注/取消关注、关注流和来源变更通知。
- 内容合规：版权授权、转载规则、敏感词、涉密检查、机器审核与人工审核工作台。
- 员工发布：草稿、富文本/附件上传、审核流、定时发布、撤回、置顶、编辑历史。
- 定向分发：按集团、分公司、部门、角色和自定义人群圈选，支持权限继承与例外名单。
- 互动数据：点赞、评论、收藏、关注、阅读进度、曝光、举报、消息通知与防刷机制。
- 搜索服务：全文检索、关键词高亮、筛选、智能/最新排序、多语言同义词与权限过滤。
- 用户信息源目录接口：提供来源列表、分类、语言、认证状态、抓取健康度、搜索与分页；支持用户订阅/取消订阅、自定义来源提交、URL/RSS/API 校验、去重和审核状态查询。
- 偏好配置服务：持久化关注来源、主题、语言、排序信号、同部门趋势授权及通知频率，提供默认值、跨设备同步、重置与变更审计；推荐和通知任务需实时消费最新版本。

### 3. 个性化推荐

- 建立内容特征、用户岗位/部门特征及阅读、停留、收藏、互动等行为事件体系。
- 召回、粗排、精排和重排服务；同时满足时效性、多样性、组织强制触达与冷启动策略。
- 推荐结果需在权限过滤后输出，并支持推荐原因解释、负反馈与用户偏好管理。
- “同部门人在看”需要基于组织关系聚合匿名阅读趋势，配置最小聚合人数并避免泄露个人阅读隐私。
- 建设离线评估、A/B 实验和线上指标监控，关注点击率之外的有效阅读与业务价值。

### 4. Studio 项目、来源选择与生成编排

- 项目服务：项目、任意层级资料子文件夹、成员、文件与 Feed 引用的持久化及资源级权限；`ProjectFolder` 只承载来源资料，不能用“生成结果文件夹”替代资产领域对象。
- 会话服务：区分项目会话与独立会话。独立会话不设置 `project_id`，消息、附件、标题、历史排序、工具选择、模型参数及恢复点单独持久化；切换项目时不得隐式迁移或复制独立会话。
- 来源选择：服务端校验逐项/全选文件的访问权限，生成稳定来源快照；文件变化或删除后仍能追溯当次生成依据。
- 上下文工程：解析被选中的 DOCX/PDF/PPTX/XLSX/Feed 引用，执行长对话压缩、知识检索、引用溯源、冲突提示与 token 预算管理。
- 模型网关：多模型路由、限流、超时、重试、内容安全、成本核算、审计与降级策略。
- 工具编排：图像、PPT、视频、翻译、文档、图表、思维导图、音频、网页等生成服务的统一任务协议。
- 异步任务：队列、实时进度事件、取消/重试、失败原因、幂等处理、任务历史分页、状态筛选与站内通知；任务菜单的预览、分享与删除均需后端鉴权，删除采用可恢复软删除并保留审计记录。
- 企业能力扩展：合同、标书、周报、流程图等能力需要独立工作流、领域提示词、校验规则和审批机制。

### 5. 企业模板中心

- 模板上传、解析、预览、版本、启停、适用组织/能力配置及默认模板规则。
- Word/PPT/PDF 的版式引擎，支持字体、母版、页眉页脚、目录、图表主题和品牌资产约束。
- 模板发布审批、灰度范围、历史版本回滚与模板使用统计。
- 生成前校验模板兼容性，生成后检查版式溢出、缺字、图片清晰度等质量问题。

### 6. 项目资产、文件与导出

- 对象存储、分片上传、病毒扫描、文件类型/大小限制、预览转码、生命周期与加密。
- 项目资产服务：将生成结果作为独立 `Artifact` 与项目或独立会话关联，并绑定生成任务、来源快照、模板、版本及创建人；资产不进入 `ProjectFolder`，需支持列表、预览、历史版本、失败任务重跑与软删除。
- 预览与导入对话：服务端负责 Office/PDF/图片/音视频的安全转码、分页与流式预览；“导入对话”创建可追溯的资产引用和版本快照，不复制二进制文件，并在模型调用前再次校验权限。
- 文档导出与打包下载：生成真实 DOCX、PPTX、PDF、图片等文件，支持单项下载、勾选资产后的异步 ZIP 打包、进度查询、短期签名下载地址、失败重试和跨平台排版一致性。
- 个人/团队知识库的目录、标签、版本、权限、全文检索、引用关系与删除恢复。
- 生成产物入库时保存来源会话、Feed 引用、模板、模型版本与创建者，满足可追溯性。

### 7. Studio 分享、消息与协同

- “分享至 Studio”需要创建项目资产、对话产物或任务结果的内部引用，选择接收项目/会话并校验双方权限，避免复制后绕过原始资源授权。
- 分享链接使用不可预测 token，支持有效期、密码/水印、访问次数、撤销与访问审计。
- 服务端实时鉴权，支持组织内公开、指定部门/人员与外部访客策略。
- 对接企业 IM、邮件与消息中心，处理发布、评论、任务完成、审核等通知。
- 若支持多人编辑，还需文档锁/协同协议、评论、版本冲突与操作记录。

### 8. 安全、合规与运营

- 传输与存储加密、密钥管理、租户隔离、数据分级、脱敏、留存与删除策略。
- 全链路审计：谁在何时读取了什么内容、向哪个模型发送了哪些数据、生成/导出了什么。
- 防提示词注入、附件恶意内容检测、模型输出审核、敏感企业信息外发控制。
- 管理后台分别服务 Feed 内容运营和 Studio 能力运营，避免审核流程混用；仅共享身份与必要引用关系。
- 可观测性：接口、任务、模型、抓取、推荐和导出的日志、指标、告警与成本看板。

## 前后端建议契约

正式开发时建议优先定义以下领域接口：`Content`、`ContentSource`、`FollowRelation`、`Project`、`ProjectFolder`、`ProjectFile`、`SourceSelectionSnapshot`、`Conversation`（允许无项目归属）、`GenerationTask`、`Artifact`（与文件夹解耦）、`ArtifactReference`、`ExportBundle`、`EnterpriseTemplate`、`KnowledgeEntry`、`ShareLink`。生成任务应返回稳定任务 ID 与可订阅的状态事件；所有内容、来源文件、任务与产物接口必须在服务端执行租户和资源权限校验。
